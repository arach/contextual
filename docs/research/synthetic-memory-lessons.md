# Synthetic Memory Lessons

Reviewed: 2026-06-02

Synthetic memory lessons are candidate mini-rules generated from source evidence
and exercised against a small practice prompt before they become durable context.
They are not raw transcript summaries and not hidden provider memory.

## Thesis

The useful unit is a lesson, not a memory blob.

A lesson should contain:

- the source ids and source refs that justified it
- the context where it applies
- the behavior it recommends
- the anti-pattern it prevents
- a practice prompt that would catch misuse
- an evaluation result before persistence

This matches the shape of in-context learning more closely than a generic memory
summary. The future agent receives a compact rule plus a miniature test case,
not just a recollection.

## Precedent

Reflexion shows that agents can improve without weight updates by storing
language reflections from task feedback as memory for future trials.

Generative Agents use observations, reflection, and planning to produce higher
level memories from raw events.

MemGPT and Letta show the value of separating always-loaded memory from larger
archival or file-backed memory.

The Contextual version should be stricter than those systems: every synthetic
lesson remains a candidate until provenance and evaluation are visible.

## Lifecycle

```txt
source evidence
  -> candidate lesson
  -> synthetic exercise
  -> evaluation
  -> accepted rule / memory / package part
```

Candidate lessons can be generated by a model or deterministic heuristic. The
important part is not the generator. The important part is the acceptance gate.

## Surfaces

| Surface | Use |
| --- | --- |
| `agent-rule` | Stable behavior a future agent should apply under a scoped condition |
| `memory` | File-backed recall that is useful but not mandatory |
| `skill` | Repeatable procedure or tool workflow |
| `package-part` | Context package material for a launch profile |
| `source-gap` | A warning that a tempting source is stale, thin, or missing |

## Acceptance Rules

A lesson should not be persisted unless it passes these checks:

- **Source-backed**: cites loaded evidence or explicitly says it is a source gap.
- **Scoped**: names where the lesson applies and does not overgeneralize.
- **Actionable**: tells the future agent what to do or avoid.
- **Exercised**: includes a prompt with expected and failure signals.

## Prototype

`POST /api/context-design/synthetic-memory`

Input:

```json
{
  "objective": "Design a file memory adapter using Letta and Codex memory patterns",
  "target": "codex",
  "maxLessons": 4
}
```

Output:

- candidate lessons
- source ids and source refs
- target surface
- evaluation checks
- Markdown-ready cards

The route does not write memory files. It only proposes candidates.
